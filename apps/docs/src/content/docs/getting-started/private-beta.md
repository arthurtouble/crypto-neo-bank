---
title: Private beta
description: How invitation and eligibility protect personal features.
---

Aura can be browsed by anyone with fictional example data. Personal records and financial actions require sign-in. During private beta, access can also require a one-use invitation, supported country, accepted terms, and available cohort capacity.

Invitation codes are issued by an authorized operator and shown once. Aura stores a hash of each code rather than the original. Do not share a code or use a code received from an untrusted source. The old public waitlist is closed; submitting an email to its former endpoint does not create an entry.

Security controls, country checks, and product availability are evaluated again when an action is prepared. An invitation does not activate bank transfers, cards, securities, rewards, or a provider service that is not connected. [See product status](/getting-started/status/).
